# 4096环境训练：重置条件与原版参数核查

核查日期：2026-10-22（Asia/Shanghai）。对象为 `logs/gap_training_4096_headless_20261021/config.json` 及对应 `terminal.log`。本次只检查代码、实际配置和日志，不修改或重启正在运行的训练。

## 1. 结论

1. 增加到4096环境/1024深度数据环境，并没有将世界模型、AMP缓存、深度预测器的轻量默认参数恢复为原版配置。PPO基本参数与网络尺寸则保留原版。
2. 当前两种组合失败率接近100%，但专用违规率通常不足1%，大部分失败来自通用终止分支。日志没有区分机身接触、向下速度超限和翻倒，尚不能确认具体哪一个占主导。
3. `Mean episode length` 是所有地形最近100个结束回合的步数平均，而非某种组合的单独均值，且不是秒。控制周期0.02秒，32步为0.64秒。并行环境同一时刻可能结束很多回合，最后100条记录也可能偏向某些环境编号。
4. 无坡组合的 `coverage=0.1667` 可能仅表示自动满足“不需要下坡”这一位，不能当作已经完成16.7%路线。
5. 动作噪声明显增长：第0轮1.01、第100轮1.70、第200轮2.25、第300轮2.79、第400轮3.40、第428轮3.55。动作缩放0.25时，3.55对应缩放前截断影响之外约0.89rad的关节目标标准差。这是需要重点排查的失稳因素，但单靠日志不能证明因果。
6. 射线相机当前绑定所有4096个机器人，得到完整射线结果后再挑1024份供训练使用。数据覆盖率为25%，射线计算环境覆盖率实际为100%，额外增加传感计算量。未选环境仍使用预测深度，不代表全体都读取真实深度。

## 2. 通用重置条件（当前五种地形都适用）

入口：`wmp_lab/logic.py:check_termination()`，由 `WMPEnv._get_dones()` 每个控制步调用。A1 `terminate_after_contacts_on=["base"]`。

| 条件 | 实际表达/阈值 | 说明 |
| --- | --- | --- |
| 机身终止碰撞 | `base`净接触力向量模长 > 1N | 单个控制步满足即可，无持续时间过滤；并非只有翻倒才终止。与原版逻辑相同，但底层测力由Gym换成Lab接触传感器，数值不能直接认为完全一致。 |
| 向下速度过大 | 世界坐标机身线速度Z < −3m/s | `root_states[:,9]` 是世界线速度Z，不是角速度。 |
| 翻倒 | 机体系重力向量Z > 0 | 对应机身倾斜超过90°。 |
| 速度偏差 | 前进指令为正时，实际机体系前进速度比目标小超过1.5m/s；后退指令为负时反向对应 | 仅 `terrain_levels>3` 生效；两种组合当前L0，因此此条件目前不会触发。 |
| 超时 | `episode_length_buf > ceil(45/0.02)` | 当前五地形配置均用45秒上限，约2250步。按超时标记返回，区别于失败。 |

坡地、原有上楼梯和原有沟壑没有新增的组合任务重置分支。它们在该混合配置中也采用45秒上限。

`stuck`、`cheat`、动作变化、竖直速度、脚缘、关节误差等常规奖励不是额外重置条件。成功要求的姿态阈值 `gravity_z<−0.8`、竖直速度绝对值<0.35m/s也不是通用失败阈值。

## 3. 两种楼梯沟壑组合的全部专用失败条件

实现：`wmp_lab/competition_tasks.py:CourseState._update_combos()`。以下均进入 `bad`，记录 `violation` 并立即重置；通用失败另被并入 `failed`。

顶面判定：脚链原点减2cm作为足底；XY需在台面边界向内5mm以内，足底与顶面高度差小于2cm；足部世界Z接触力>1N才记支撑。

| 条件 | 触发方式 |
| --- | --- |
| 错误落脚 | 记录过全足腾空之后、完整落台之前，任一脚接触非目标落地台。包括腾空后又碰回起跳台，当前实现会判失败。 |
| 未跳直接跨台 | 尚未记录全足腾空，却已支撑目标落地台。即使L0缺口仅5cm，也要求真实腾空，不允许直接迈过去。 |
| 跳过台阶 | 机身X超过起跳台中心前侧附近（中心X−0.2m），仍未按顺序支撑两级台阶。 |
| 脚掉入缺口 | 脚在起跳台与落地台之间，足底低于起跳台面2cm以上；无需等碰到底部。 |
| 脚掉到赛道侧边 | 脚Y超出±0.4m，足底低于该X处赛道高度2cm以上。 |
| 非法足部接触 | 任一脚有>1N的Z向接触，但不符合任何台面顶面支撑或合法坡面支撑；垂直面接触和边界附近接触可能被排除。 |
| 机身横向出界 | 机身局部Y绝对值>0.4m，不要求已经触地或掉低。 |
| 机身坠落 | 世界机身Z<−0.15m。 |
| 超出无坡末端 | 仅 `stair_gap`：机身X超过落地台末边，直接终止，防止跑入末端深沟。 |

成功也会重置：完成楼梯及合法跳跃，四足先后都有目标顶面支撑记录、当前四足均在落地台XY范围且至少两足支撑。无坡版在末台稳定0.3秒成功；带坡版还需有效支撑坡面、全足进入坡底终点平地并稳定0.3秒。到达完整终点支撑条件后指令置零。

专用规则确实严格，尤其“单步非顶面接触”和“首次腾空后碰回起跳台”，但目前违规率不能支持把它们当作主要早停原因。

## 5. 出生状态与回合统计

当前两种组合从合法入口平地起步，机身Z为路面+0.35m；重置X扰动约±2.5cm、初始关节为默认站姿的95%–105%，初始根线速度/角速度为0，不使用AMP参考状态初始化，也不接受随机推搡。关节和主机身姿态定义仍来自原版A1资产。

旧三种通用地形沿用较宽的关节随机化（默认关节角乘0.5–1.5）、初始根速度±0.5和原有随机推搡。地形不同，不应使用全体回合的单一均值归因。

`logic.reset_idx()`将回合标志置1是重置帧的协议，不会自动证明下一回合被无条件立即终止；下一次 `check_termination()` 会重新赋值。初始随机回合长度只在训练开始设置一次，并非每次随机截断。

阶段统计是每次重置时的批内均值，再由日志求平均，不是统一时间窗口内逐回合加权通过率。`standard_attempts`只指L6，`target_attempts`只指L9；L0时二者为0不表示没有训练尝试。

## 7. 建议的下一步

先增加按地形统计的终止原因和回合长度，分别记录机身接触、翻倒、快速下落、每条组合规则以及首次台阶接触前后的失败；再用已保存检查点做少量环境的确定性/随机动作对比，观察动作噪声是否导致多数摔倒。诊断应避免与4096主训练争抢大量显存。

确认原因后再决定修改重置规则、限制/调整探索噪声或调整奖励。若要恢复原版世界模型/深度预测器参数，应先做显存与训练时长预算；将深度预测器1000次更新直接放回当前配置，可能大幅延长每10轮的用时。当前核查没有修改训练或直接切换参数。

## 8. 恢复更新量的可行性补充

保留的第一次10000轮训练实际使用2048环境、512深度数据环境、48步PPO采样，以及原版16×64×10的世界模型和1024×1000的深度预测器；当时整卡峰值12457MiB。其每轮PPO样本量2048×48与当前4096×24相同，不能将当时的全部内存简单乘2。但当前物理环境、射线计算量和45秒CPU轨迹缓存更大，不能据此保证4096全量参数一定装得下。

从该次TensorBoard事件时间戳计算第50–500轮的中位耗时：世界模型10步更新约1.726秒；深度预测器每次1000步更新约46.662秒（每10轮一次，平均约4.666秒/轮）。这是同机历史实测，尚非当前4096环境的完整资源测试。

更新次数增加通常主要增加时间，不按次数成倍增加显存；批量和序列长度增加才明显增加激活/梯度峰值。建议先恢复世界模型10次更新、序列长度64，批量由4逐步增至8；深度预测器先恢复1000次更新，批量由256增至512；最后再测试原版16与1024批量。8×64×10和512×1000均为原版名义样本预算的一半，256深度批量为1/4；不等同于原版训练效果。

AMP预加载200万和回放100万可以纳入恢复计划：相对当前的常驻GPU张量粗算增加约0.9GiB，初始化临时张量还会额外占用。主机可用内存、CUDA峰值和训练吞吐量均需同时观察。上述分阶段参数是建议，没有改变当前运行。

## 9. 动作噪声机制与历史对照

`ActorCriticWMP.std`是12个全局可学习参数，每个关节一个，不是按状态单独预测的噪声。动作按高斯分布采样，PPO损失包含 `−0.01×entropy`，熵为各关节 `log(std)` 加常数之和，因此熵项本身推动标准差增大。当前实现只有最小标准差约束，没有上限；PPO/KL限制单次变化，不能阻止多轮累积增大。

原版第一次10000轮实测：标准差第100/200/300/400轮为0.559/0.483/0.456/0.443；对应混合回合长度约669/677/741/579步。当前第100/200/300/400轮标准差为1.70/2.25/2.79/3.40，对应混合回合长度约23/23/22/36步。地形和采样步数不同，因此这不是受控实验，但说明本机和同套熵系数并不必然导致标准差上涨。

当前普通运动奖励先把总和截到0以上，`termination=0`；组合任务另减5的条件是专用 `bad`，不是含所有通用终止的 `failed`。因此机器人在进入障碍前因机身接触/翻倒终止，没有该项−5罚分。高动作噪声导致动作变化等负项变大时，普通奖励可能大量落在0平台区，无法继续表达“更坏”的差别；这会减弱PPO目标对抗熵项的信号。它构成可能的反馈循环，不证明所有标准差梯度均来自熵，也不证明机器人有意逃避处罚。

代码中的AMP混合标志0.3实际只决定是否调用相加函数，`_lerp_reward()`返回 `disc_r + task_r`。按第266轮判别值约−0.874估算AMP单步奖励约0.00122，已经明显偏低；AMP判别器损失不会直接对策略std反传，它通过采样得到的AMP奖励间接影响PPO。专家预加载/回放变小，以及预测深度/世界模型学习偏弱，也可能降低可用反馈质量，但当前没有梯度分项或对照试验来量化各自贡献。

标准差3.55乘0.25得到的0.89rad是截断前关节目标噪声尺度，不是实际关节每步转动51°。动作还会裁剪到±6，PD目标偏移被限制到±1.5rad，随后受力矩限制和机器人动力学约束。即便如此，高噪声会增加目标跳变、力矩饱和、机身触地和短回合概率，还会使未经截断动作与真正执行动作之间的差异变大，削弱样本效率。为示意：若某关节均值为0且std=3.55，高斯样本超出±6的概率约9%；实际每关节std与均值不相同，须从回放测量实际裁剪比例。

目前PPO学习率第100–400轮在约0.000256–0.000577，与历史训练处于相近量级，没有发现当前一直顶着0.01学习率运行的证据。单独把问题归咎于学习率或熵系数不成立。

建议优先级：按地形统计重置原因和实际动作裁剪/力矩饱和；用确定性和随机策略回放做对比；统一通用失败与任务失败的奖励口径；再评估探索标准差上限/熵退火与模型更新量恢复。仅增加世界模型更新不能保证修复标准差持续增长。
